## Reproduction and resolution

Five actual-production-script regressions failed on the original candidate: a delayed OAuth exchange overwrote a newer email session; even a failed explicit email attempt was later replaced by background OAuth; a delayed rejected refresh erased a newer account; a fresh OAuth failure silently continued as a different healthy cached account; and a provider outage deleted a recoverable credential. [Original failure evidence](evidence/public-oauth-before.log).

Every email, provider startup, OAuth restoration, refresh and delayed navigation now retains a captured intent version plus the exact app and connected-account records. New explicit intent or an observed cross-tab account change invalidates older continuations. Failed explicit attempts still supersede background restoration. Provider startup disables SDK automatic navigation and rechecks the captured account before following its returned HTTPS URL. Bounded requests retain reachable retry controls and remove both loading overlays on failure.

A fresh provider callback must receive a coherent full app-user session for the same provider email. Failed sync cannot claim success from an unrelated cached account. Ordinary visits with an app credential use that credential's repair path, avoiding silent selection of a lingering provider account. Refresh uses the token account claim as the owner when present, validates the replacement user and preserves transiently uncheckable sessions. Only a current expired/rejected credential is cleared. Preboot uses the same expiry and owner consistency rules, so it cannot redirect before damaged records are repaired. Claims inspection is a client consistency check, not signature verification or a replacement for server authorization.

Explicit sign-out removes only the known app/provider credentials synchronously and sends the captured old provider token to Supabase's logout endpoint. It preserves the previous global logout scope while preventing asynchronous SDK local-storage cleanup from erasing a later sign-in. Failed remote logout is described as confirmed local sign-out with unconfirmed other-device revocation. The temporary analytics client does not persist or refresh old OAuth state; a subsequent explicit provider flow uses a fresh normal client. This follows the primary [Supabase logout contract](https://github.com/supabase/auth/blob/master/openapi.yaml) and preserves the existing [global sign-out scope](https://supabase.com/docs/reference/javascript/auth-signout). Offline league/profile records remain outside this bounded change.

ESPN-only guests and signed-in users now count as connected in landing routing. Fresh-account setup clears the prior ESPN league/year and both local/session cookie copies, the previous MFL API key and guest flag. A new-account handoff cannot be diverted by old guest state. Unrelated offline work is preserved; the full ownership migration of legacy profile/league stores remains separate.
