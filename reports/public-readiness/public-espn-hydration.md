# Public ESPN hub recovery — 2026-09-20

Candidate branch `codex/public-espn-recovery-20260920`, based on actual public `012a897`. Root integrates with the reviewed public connection/OAuth/dependency candidate. No native source, canonical shared module, provider account or remote data was changed. No deployment is claimed.

## Reproduction and resolution

**High — saved ESPN connection disappears at the hub.** Actual baseline `012a897` `OwnerDashboard` received a valid controlled account and saved `espn_league_id=123`, `espn_year=2025`. Chrome observed zero ESPN requests, no recovery panel and no team handoff. The old hidden connector was the only caller, and it used `ESPN.connectLeague`, which mutates the active global league bridge. [Baseline evidence](evidence/espn-hub-baseline.json), [screenshot](evidence/espn-hub-baseline.png).

`js/espn-hub.js` now loads the saved exact ID/season through the existing pure `fetchLeague`, `buildCrosswalk` and `mapToSleeperState` exports. It never calls the mutating legacy connector or updates `window.S`. Successful responses must include the expected season/league when identified, complete unique teams/rosters and scoring/roster settings. Failed, partial, foreign and timed-out responses cannot become empty success. The hub shows loading, retry and session-only private-cookie recovery; an ordinary provider failure retains previously loaded data with an explicit stale-data sentence. Account/connection invalidation clears the old ESPN hub entries and typed cookies. The previously permanent “Loading more leagues” message from a never-started Sleeper request is corrected.

**High — ESPN has no selected team in the league view.** The existing league view matched rosters to the Sleeper user ID. A connected ESPN user now explicitly chooses a returned team before opening. The choice is saved under account + league + season; a failed save retains the chooser and reports failure. Reload reuses a still-existing team, and a missing team requires a new choice. `LeagueDetail` resolves the selected ESPN roster again after hydration, including its owner for the current view, rather than substituting a Sleeper match or an old removed roster. Deep-link tabs, hub return, keyboard entry and remount on a different ESPN league/team are covered.

Account snapshots guard each asynchronous publication and connection save. Server authorization is unchanged: local token checks are only a client consistency guard. Root's independent review found that the first helper version could accept conflicting/missing owner claims; it now requires three token segments, finite live expiry and both `sub` and `app_metadata.user_id` equal to the cached account ID. Exact negative fixtures cover missing/conflicting claims and infinite/string expiry. Explicit guest mode is supported; a stale guest flag cannot override a valid signed-in account. Cross-tab provider/account changes invalidate the pending snapshot even when storage bytes return to their earlier value.

## Limits and next steps

Root's complete independent source review and integrated public release checks remain pending. This batch restores the hub-to-league contract; it does not declare the full ESPN product ready. Provider-authorized public/private live requests, real roster/statistic truth and the entire engine after hydration still need integrated runtime proof. Existing broad account-scoping of legacy profile/provider records and downstream asynchronous engine/cloud writes are separate required work. No existing source was hidden to avoid these checks.

The actual public index admits a `fw_session_v1` app session or explicit guest mode. It does not admit an `od_session_v1`-only legacy visitor: that visitor is already routed to landing sign-in. The shared client still contains a legacy token fallback, so legacy-session migration must remain documented rather than being silently counted as supported by this new helper. The helper preserves existing legacy data and does not infer an account owner from a Sleeper username. The guest ESPN route is separately covered in the reviewed connection-page/index batch and in the helper regression.

The existing ESPN mapper/provider retains its supported capabilities and valuation contract. This change does not invent drafts, future picks, matchups, historical chains, keeper economics, live scores or access entitlements. Root owns the later Trade Center format/remaining-capital caller correction and coordinated shared publication.
