## Independent review follow-up: resolved identity and roster evidence

Root review identified a successful but unrelated user response boundary. The exact new actual-helper regression failed on `d857648`: request `Alice`, response `{user_id:'999',username:'Bob'}` published Bob and fetched his leagues. The correction rejects before any league-list follow-up unless the returned username matches the requested username (case-insensitively) or the requested identifier exactly matches the returned user ID. Existing valid same-username/new-ID handling remains supported and cannot borrow the prior user's cached leagues. A mismatched response can retain only the prior verified same-account snapshot, explicitly stale with an unverified denominator. [Sleeper's primary user contract](https://docs.sleeper.com/#user), retrieved September 20, 2026, documents lookup by username or user ID and warns that usernames can change; accepting case differences is the existing product's username normalization policy.

Roster evidence now rejects an absent `players` field and rejects `null` for an active/completed league. Explicit arrays, including `[]`, remain known holdings. The narrow accepted pre-draft interpretation is explicit `null` in `pre_draft` or `drafting`: this becomes `[]` with `_portfolioPlayersEvidence:'pre-draft-empty'` retained. This interpretation is deliberately limited to an unfilled draft roster, not a general null-to-zero conversion. Missing player data during refresh retains the prior card marked stale. Missing win/loss/tie fields remain nullable; downstream Empire must preserve that distinction.
